# Adaptive Literature Review Agent

**연구주제나 연구계획서를 주면, 핵심 선행연구 20편을 찾아 읽고 비교해 "내 연구에 어떻게 쓸지"까지 정리해 주는 Claude Code 에이전트입니다.**
연구계획이 바뀌거나 새 질문이 생기면, 부족한 부분만 골라 문헌을 더 찾아 결과를 갱신합니다.

*An adaptive literature discovery, analysis, and synthesis workflow for Claude Code.*

https://github.com/user-attachments/assets/ac382c96-bfc7-4076-b0d0-20296674a76f

| 이런 일을 대신합니다 | 이런 것은 하지 않습니다 |
|---|---|
| 분야별 주요 학술지부터 검색하고 인용망으로 넓혀 핵심문헌 선정 | 없는 논문·DOI·인용문·쪽수를 만들어 내기 |
| 공개 원문(OA) 확보, 못 구한 논문은 요청 목록으로 정리 | 유료 논문 우회 다운로드, 원문 재배포 |
| 논문마다 분석카드와 원문 위치가 확인된 인용 근거 작성 | 초록만 본 논문을 원문을 읽은 것처럼 정리 |
| 내 연구계획서의 장·절·가설별로 쓸 문헌과 서술 방향 제안 | 연구공백·최종 인용 여부를 대신 결정 |

## 5분 만에 시작하기

### 준비물

- [Claude Code](https://claude.com/claude-code) (데스크톱 앱 또는 CLI)
- Python 3.10 이상
- 인터넷 연결

> PDF 처리에 쓰는 [PyMuPDF](https://pymupdf.readthedocs.io/)는 **AGPL-3.0(또는 상용) 라이선스**입니다. 이 저장소는 MIT이지만, 도구를 웹 서비스로 제공하거나 다른 프로그램과 묶어 배포하려면 PyMuPDF의 AGPL 조건을 따로 확인하세요.

### 1단계 — 내려받고 설치하기

이 저장소를 내려받은 뒤, 폴더 안에서 패키지를 설치합니다.

```bash
python -m pip install -r requirements.txt
```

설치가 잘 됐는지 확인합니다. 처음 실행하면 작업용 폴더(`raw/ state/ library/ out/`)가 자동으로 생깁니다.

```bash
python .claude/skills/adaptive-literature-review/scripts/lra.py status
```

### 도구 설치 위치와 연구 폴더 분리 (선택)

기본은 **이 저장소 폴더 안에서 연구**하는 방식입니다. 연구 주제마다 저장소를 새로 받기 싫거나 도구와 연구 자료를 따로 두고 싶다면 이렇게 하세요.

1. `.claude/skills/adaptive-literature-review` 폴더를 `~/.claude/skills/`(모든 프로젝트에서 사용) 또는 연구 폴더의 `.claude/skills/`에 복사합니다. 명령 경로는 Claude Code가 `${CLAUDE_SKILL_DIR}`로 알아서 맞춥니다.
2. 승인 확인 창을 쓰려면 저장소의 `.claude/settings.json` 내용을 `~/.claude/settings.json`이나 연구 폴더의 `.claude/settings.json`에 합쳐 넣습니다.
3. Claude Code를 **연구 폴더에서** 열면 `raw/ state/ library/ out/`이 그 폴더에 생깁니다. 직접 실행할 때 다른 폴더를 지정하려면 `--root`를 씁니다.

```bash
python ~/.claude/skills/adaptive-literature-review/scripts/lra.py --root ~/research/rd-subsidy status
```

### 2단계 — OpenAlex API 키 넣기 (권장)

논문 검색은 무료 학술 DB인 **OpenAlex**를 씁니다. 키 없이도 동작하지만, 키를 넣으면 하루 검색량이 크게 늘어납니다. 키는 [OpenAlex 설정 페이지](https://openalex.org/settings/api)에서 무료로 받을 수 있습니다.

<table>
<tr><th>macOS · Linux</th><th>Windows (PowerShell, 한 번만 실행)</th></tr>
<tr><td>

```bash
export OPENALEX_API_KEY="발급받은_키"
```

</td><td>

```powershell
setx OPENALEX_API_KEY "발급받은_키"
```

</td></tr>
</table>

Windows의 `setx`는 **새로 여는 프로그램부터** 적용되므로, 실행한 뒤 Claude Code를 완전히 닫았다 다시 여세요.
환경변수 대신 `state/config.json` 파일에 `{"openalex_api_key": "발급받은_키"}`로 넣어도 됩니다. 이 파일은 GitHub에 올라가지 않습니다.

### 3단계 — 폴더를 열고 말로 요청하기

Claude Code에서 이 폴더를 열고 연구주제를 말하면 됩니다. 연구계획서가 있으면 `raw/` 폴더에 넣어 두세요(PDF·DOCX·MD).

```text
"공공 R&D 보조금이 중소기업 혁신에 미치는 효과로 선행연구를 조사해줘."
```

끝나면 `out/11_선행연구_종합보고서.md`부터 열어 보세요.

| 하고 싶은 일 | 이렇게 말하세요 |

| 내가 아는 논문 추가 | "DOI 10.xxxx/xxxx 논문도 넣어줘" |
| 순위 조정 | "P-007을 1순위로 고정해줘" · "관련성 가중치를 40%로 올려줘" |
| 문헌 교체·제외 | "P-012는 주제와 달라서 빼줘" |
| 원문을 직접 구했을 때 | `raw/fulltext/P-007.pdf`로 넣고 "원문 넣었어, 반영해줘" |
| 계획서가 바뀌었을 때 | "raw/연구계획서_v2.pdf 올렸어. 바뀐 부분에 맞춰 문헌 보완해줘" |
| 분석 중 생긴 질문 | "DID 방법을 쓰려는데 근거 문헌이 충분한지 봐줘" |
| 국내 논문까지 | "KCI 논문도 같이 찾아줘" (KCI 인증키 필요 — [구현 현황](#구현-현황과-한계) 참고) |

`P-007` 같은 번호는 에이전트가 논문마다 붙이는 고유 번호입니다. 결과물 어디서든 같은 번호로 가리킵니다.

## 진행 순서와 내가 확인할 지점

```text
 연구주제 / 연구계획서
        │
        ▼
 ① 연구 맥락 정리 ··········· 연구질문·변수·방법 정리, 모르는 것은 '미정'으로 표시
        │                     ◀ 확인: 정리된 내용과 검색어, 우선 학술지 목록
        ▼
 ② Stage A — 우선 학술지 검색 ·· 분야별 주요 학술지·학회 5~10곳부터
        │
        ▼
 ③ Seed 3편 선정 ············ 이론 · 방법론 · 유사 실증 대표 논문 1편씩
        │                     ◀ 확인: Seed 3편과 대안
        ▼
 ④ Stage B — 인용망 확장 ······ 참고문헌·후속 인용·유사 논문 (학술지 제한 없음)
 ⑤ Stage C — 독립 검색 ········ 인용망 밖에서 놓친 논문 점검 (반드시 1회 이상)
        │
        ▼
 ⑥ Core 20편 + 중요도 순위 ···· 이론 6 · 방법론 6 · 실증 8 기준(조정 가능)
        │                     ◀ 확인: Core 목록과 순위
        ▼
 ⑦ 원문 확보 → 분석카드 → 인용 근거 → 비교분석 → 활용계획 → 종합보고서
        │
        ▼
 ⑧ 자동 검증 ················ out/16_검증결과.md (FAIL 0건이 목표, INSUFFICIENT·N/A는 '검증 안 됨'으로 따로 표시)
        │
        ▼
 계획 변경·새 질문 → 부족한 영역만 추가 탐색(Extended)
```

- **◀ 확인** 표시에서 에이전트가 멈추고 의견을 묻습니다. "알아서 진행해줘"라고 하면 멈추지 않고 진행하되, 결과물에 **임시선정**으로 표시합니다.
- 승인은 대화로 하면 됩니다. "Seed는 승인, Core에서 P-012는 빼줘"처럼 말하세요.
- 처음에 고른 학술지는 **검색 순서**일 뿐입니다. 목록 밖의 논문도 같은 기준으로 선정합니다.

## 논문 중요도 순위

비슷해 보이는 20편 중 **무엇을 먼저 읽고 인용할지** 정하기 위한 순위입니다.

| 기준 | 기본 가중치 |
|---|---:|
| 연구질문 직접 관련성 | 35% |
| 연구 내 역할·기여도 | 25% |
| 연구설계·근거의 적절성 | 20% |
| 정보의 차별성·보완성 | 10% |
| 연구시점 적합성 | 10% |

- 기준마다 0~5점을 근거 문장과 함께 매기고, 0~100점으로 환산합니다.
- **인용 수나 학술지 순위는 점수에 넣지 않습니다.** 참고 정보로만 따로 표시합니다.
- 판단할 근거가 없는 기준(예: 초록이 없는 논문의 연구설계)은 점수를 지어내지 않고 **평가보류**로 둡니다.
- 가중치 변경, 순위 고정(Pin)을 할 수 있고, 바뀐 이력은 모두 남습니다.
- 이 순위는 **내 연구계획 기준의 상대적 우선순위**이며, 논문의 절대적 가치를 뜻하지 않습니다.

## 믿을 수 있게 만든 장치

| 걱정 | 이렇게 막습니다 |
|---|---|
| 없는 논문이나 DOI를 지어낼까? | 논문은 OpenAlex·Crossref에서 실제로 조회된 것만 등록합니다. 서지정보는 Crossref와 자동 대조합니다 |
| 에이전트가 내 승인 없이 진행할까? | 승인·순위 고정·검색 모드 변경 같은 결정 명령은 실행 전에 Claude Code가 확인 창을 띄웁니다(`.claude/settings.json`, 권한 우회 모드에서는 뜨지 않음). 승인 기록에는 승인자와 승인 발화가 남습니다 |
| 인용문이나 쪽수가 틀릴까? | 직접 인용문은 다운로드한 원문 텍스트와 대조해 일치할 때만 "확인됨"으로 표시합니다. 공백·따옴표·괄호 같은 표기 차이는 무시하지만 숫자·소수점·부호·부등호·%는 그대로 비교합니다. 4어절 미만의 짧은 인용, 여러 쪽에 나오는데 쪽을 적지 않은 인용은 확인됨으로 표시하지 않습니다 |
| 초록만 보고 다 읽은 척할까? | 원문·초록·서지정보 중 무엇을 근거로 했는지 논문마다 표시합니다 |
| 철회된 논문이 섞일까? | Crossref·Retraction Watch 정보로 정정·철회 여부를 확인해 표시합니다 |
| 같은 논문이 두 번 들어갈까? | DOI·제목·저자로 프리프린트와 출판본을 묶어 한 편으로 셉니다 |
| 특정 학술지에 치우칠까? | 우선 학술지 검색 뒤에 학술지 제한 없는 인용망·독립 검색을 반드시 거칩니다 |
| 최종 점검은? | `lra.py verify`가 위 항목과 순위 계산을 다시 검사해 `out/16_검증결과.md`로 남깁니다 |

## 자주 묻는 질문

<details>
<summary><b>비용이 드나요?</b></summary>

OpenAlex·Crossref·Semantic Scholar는 무료로 쓸 수 있습니다. OpenAlex는 하루 사용량 한도가 있으며, 키가 없으면 같은 네트워크의 사용자들이 작은 한도를 함께 씁니다. 무료 키를 받으면 개인 한도가 생깁니다(2026년 10월 확인 기준, 정책은 바뀔 수 있음). 20편 조사 1회에 검색이 수십 번 정도 쓰입니다. 같은 검색을 반복하면 저장해 둔 결과를 다시 써서 한도를 쓰지 않습니다. Claude Code 사용 요금은 별도입니다.

</details>

<details>
<summary><b>유료 논문은 어떻게 하나요?</b></summary>

에이전트는 공개(OA)로 표시된 원문만 내려받습니다. 못 구한 논문은 `06_원문다운로드_요청목록.md`에 정리됩니다. 기관 구독 등 정당한 권한으로 받은 PDF를 `raw/fulltext/P-007.pdf`처럼 **번호를 파일 이름에 넣어** 두고 "원문 넣었어"라고 말하면, 그 논문을 원문 기반으로 다시 분석합니다.

</details>

<details>
<summary><b>내 연구계획서가 외부로 전송되나요?</b></summary>

학술 DB에는 **검색어와 DOI만** 보냅니다. 연구계획서 원문은 보내지 않습니다. 다만 Claude Code가 계획서를 읽고 분석하는 과정은 Claude Code의 데이터 정책을 따릅니다. 미공개 고유명사나 수치는 검색어에 넣지 않도록 설계되어 있습니다.

</details>

<details>
<summary><b>20편이 안 나오면요?</b></summary>

20편은 목표일 뿐입니다. 관련성 낮은 논문으로 채우지 않고, 부족한 수와 이유를 보고서에 적습니다.

</details>

<details>
<summary><b>중간에 멈췄다가 이어서 할 수 있나요?</b></summary>

네. 모든 진행 상황이 `state/literature.db`에 저장됩니다. "이어서 해줘"라고 하면 현재 단계를 확인하고 계속합니다.

</details>

<details>
<summary><b>이게 체계적 문헌고찰(Systematic Review)인가요?</b></summary>

아닙니다. 검색 기록을 재현할 수 있게 남기지만, 결과물은 **서술적 문헌검토**입니다. 정식 체계적 문헌고찰을 수행했다고 표현하지 않습니다.

</details>

<details>
<summary><b>명령어를 직접 쓸 수도 있나요?</b></summary>

대화로 충분하지만, 도구를 직접 실행할 수도 있습니다. 프로젝트 폴더에서 실행하세요.

```bash
python .claude/skills/adaptive-literature-review/scripts/lra.py -h
```

| 명령 | 하는 일 |
|---|---|
| `status` | 현재 진행 상황 |
| `search` · `expand` | 검색(Stage A·C) · 인용망 확장(Stage B) |
| `source find/add` | 우선 학술지 찾기·등록 |
| `candidates` · `select` · `deselect` | 후보 보기 · Core 선정 · 제외(삭제 아님) |
| `rank score/pin/weights` | 중요도 점수 · 순위 고정 · 가중치 |
| `fetch` · `ingest-fulltext` | 공개 원문 받기 · 직접 구한 원문 넣기 |
| `render` · `verify` | 결과물 만들기 · 자동 검증 |

입력 형식은 `.claude/skills/adaptive-literature-review/references/formats.md`, 전체 절차는 `SKILL.md`에 있습니다.

</details>

## 폴더 구조와 데이터 보호

```text
.
├── README.md · LICENSE · requirements.txt
├── CLAUDE.md                    이 폴더에서 일하는 Claude용 짧은 지침
├── .claude/settings.json        승인 등 결정 명령의 확인 창 설정
├── tests/ · pytest.ini          자동 테스트(개발용)
└── .claude/skills/adaptive-literature-review/
    ├── SKILL.md                 절차와 판단 원칙
    ├── references/              입력 형식, 보고서 템플릿
    └── scripts/                 lra.py 명령행 도구와 모듈

── 실행하면 생기는 내 작업 폴더 (GitHub에 올라가지 않음) ──
raw/        내가 넣은 연구계획서·원문 (에이전트는 수정하지 않음)
state/      진행 상황 DB, 검색 캐시, 설정(API 키)
library/    내려받은 논문 원문
out/        결과물
```

이 저장소의 `.gitignore`는 **허용 목록 방식**입니다. 위 배포 파일만 허용하고 나머지는 전부 제외합니다. 그래서 같은 폴더에서 실제 연구를 해도 연구계획서·결과물·원문 PDF·API 키는 커밋되지 않습니다. 새 파일을 배포하려면 `.gitignore`에 `!/파일이름` 줄을 추가하세요.

## 구현 현황과 한계

| 기능 | 상태 |
|---|---|
| 기본 문헌조사(맥락 분석 → 검색 → Core 선정 → 원문 → 분석 → 보고서 → 검증) | 구현 |
| 논문 중요도 점수·순위 | 구현 |
| 계획 변경·질문에 따른 추가 탐색 | 기본 흐름 구현 |
| BibTeX 내보내기 | 구현 |
| KCI·국내외 통합 검색 | KCI Open API 명세대로 구현했으나 **실제 응답으로 검증되지 않음**. 인증키를 넣고 `lra.py kci probe`를 통과해야 켜짐 |
| Zotero 연동 · 신규 문헌 자동 모니터링 | 향후 개발 |

- 검색 범위는 OpenAlex(와 보조 DB)의 수록 범위를 넘지 못합니다. 국내 문헌은 KCI 모드가 켜지기 전까지 거의 포함되지 않습니다.
- 공개 원문 중 상당수는 출판본이 아니라 투고본·저자 원고입니다. 결과물에 판본이 표시되며, 쪽수·수치는 인용 전에 출판본과 대조하세요.
- 검색 포괄성, 추출 정확도, 시간 단축 효과는 아직 정량 평가하지 않았습니다.
- 쪽마다 반복되는 머리말·바닥글은 아직 걷어내지 않아, 쪽 경계에 걸친 인용은 확인되지 않을 수 있습니다.

### 개발자용: 테스트

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

`tests/`는 네트워크 없이 돌아가며 GitHub Actions(Ubuntu·Windows, Python 3.10·3.12)에서 PR마다 실행됩니다.

## 학술적 사용 시 유의사항

- DOI·저자·출판정보는 인용 전에 원출처에서 한 번 더 확인하세요.
- 논문 선정, 연구공백 판단, 최종 인용 여부는 연구자가 결정합니다.
- 공개 원문이라도 저장·재배포 조건은 각 라이선스를 따르세요. `library/`의 원문은 공유하지 마세요.
